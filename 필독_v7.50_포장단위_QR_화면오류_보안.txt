FIRST OMS / 땡라이브 v7.50

[핵심 수정]
1. 화면에 자바스크립트 코드가 노출되거나 화면이 튀던 오래된 출력 템플릿 구조를 정리했습니다.
2. 택배 포장표를 고객번호/닉네임/실제포장수량 중심으로 재구성했습니다.
   - 일반: 검정
   - 김치: 주황
   - 누락/재발송: 빨강
   - 김치+누락: 보라
   - 서비스 상품: 파랑
3. 포장표와 색상구분 정산서에 바코드 대신 QR을 사용합니다.
4. 상품별 포장단위 설정을 추가했습니다.
   - 판매단위
   - 1판매단위 구성수량
   - 구성단위
   - 실제 포장단위
   예) 양말 2세트, 1세트=6켤레, 실제단위=묶음 -> 2묶음 / 총 12켤레
       만두 2세트, 1세트=3봉지, 실제단위=봉지 -> 6봉지
5. 고객별 종이 포장표 / 모바일 포장화면 / 상품 준비 총괄표에 같은 자동환산을 적용합니다.
6. 옵션이 다르면 품번이 같아도 준비표에서 별도 행으로 집계합니다.
7. 택배팀은 로그인하지 않습니다. 최초 1회 포장자 이름을 기기에 저장합니다.
8. 다 넣었어요 -> CJ 송장 바코드 필수 스캔 -> 정상 확인 -> 고객 배송문자 1회 -> 다음 고객 자동 표시 흐름을 유지합니다.
9. 포장팀 공개 API는 랜덤 접근키가 있어야 동작합니다. 접근키는 관리자 화면에서만 발급되며 필요 시 재발급할 수 있습니다.
10. 보안 헤더, 동일 출처 CORS, API Secret/택배 비밀번호 화면 비노출을 유지합니다.

[중요]
- OMS에서 출력하는 종이에는 QR을 사용합니다.
- 실제 CJ대한통운 송장 자체는 CJ 바코드를 카메라로 스캔합니다.
- Render의 기존 data 폴더는 삭제/초기화/덮어쓰기 하지 마세요.
- 땡라이브 FIRST-0001 고객DB 복구자료와 기존 서버 데이터는 보존합니다.
